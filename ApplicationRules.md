# Russian Learning App: Master Rules (Single Source of Truth)
Version: 1.0 (merged)

These rules are ALWAYS-ON constraints for every lesson, flashcard, exercise, UI rendering, and audio/narration metadata generated by the app/AI.

---

## 0) Prime Directive
Generate lessons that create durable learning, not “feels good” exposure.
Every lesson must be a closed loop:
Teach → Drill → Recall → Use → Review

If any part is missing, the lesson is invalid.

---

## 1) Closed-Loop Lesson Structure (Mandatory)

### 1.1 Teach
- Introduce 3 to 7 new items maximum (vocab and/or one grammar point).
- Provide for each new item:
  - meaning (EN)
  - stress info (stress_cyrillic preferred)
  - short usage note

### 1.2 Drill (Recognition)
- Fast tasks: match, choose translation, pick correct form.

### 1.3 Recall (Production)
- Must include user output: typing OR speaking.
- Avoid “tap only” lessons.

### 1.4 Use (Micro-context)
- Include one tiny real sentence or a micro-dialogue.

### 1.5 Review (SRS Scheduling)
- Tag items for spaced repetition: minimum 1d, 3d, 7d, 14d.
- Output review metadata for scheduling.

---

## 2) Lesson Contracts (Keep the AI on Rails)
The AI must NEVER freeform lesson generation without a Lesson Contract.

A Lesson Contract must define:
- Target level: A1 / A2 / B1
- Theme: e.g., family, food, travel
- Constraints:
  - max new vocab count
  - max sentence length
  - allowed grammar points
- Required outputs:
  - vocab list
  - example sentences
  - exercises
  - answers + brief explanations
  - SRS tags
  - voice narration metadata (see Section 11)

---

## 3) Teach Russian Where Learners Actually Struggle (Priorities)
Russian difficulty is mostly from:
- Cases (стол → на столе)
- Verb aspect (делать vs сделать)
- Motion verbs (идти/ехать/ходить/ездить)
- Stress + vowel reduction (mandatory attention)
- Gender & agreement (новый стол / новая книга)

Rule:
- Introduce these early, but gently.

---

## 4) Transliteration Policy (Short-Term Only)
Transliteration is allowed briefly, then must be phased out.

Best practice:
- Week 1: transliteration optional
- Week 2+: hide transliteration by default (“tap to reveal”)

Always show one of:
- Stress marks on new words (preferred): семья́
- or a consistent stress cue system

Goal:
- Learners internalize Cyrillic shape + sound.

---

## 5) Minimal Pairs and Micro-Contrasts (Preferred Teaching Style)
Avoid random examples. Use contrast that teaches.

Rule for grammar points:
- For each new grammar point, generate 3 paired sentences that differ by only one element.
- Include a one-line explanation of that difference.

---

## 6) Exercises Must Force the Right Struggle
Recommended exercise types:
- Case chooser: на стол__ → столе
- Gender agreement: нов__ книга → новая
- Aspect choice: did/was doing → сделал/делал (context-dependent)
- Word order swaps: same meaning, different emphasis
- Listening dictation (TTS supported)

Each exercise MUST include:
- Correct answer
- Common wrong answer(s)
- 1-line explanation

---

## 7) Quality Gate (Validation Before User Sees Anything)
If validation fails: regenerate that item/module.

### 7.1 Script & Encoding Rules
- Russian text fields: Cyrillic-only (plus punctuation/spaces).
- Transliteration fields: Latin-only.
- Never allow mixed-script lookalikes (e.g., cmole).

### 7.2 Content Consistency Rules
- Target word must appear in the example sentence (or correct inflected form).
- English prompt must match the meaning used in the Russian example.
- Translations must be consistent and natural.

---

## 8) Personalization Rules (Use Carefully)
Personalization that helps:
- user-relevant topics
- familiar names/places
- pacing based on performance

Personalization that hurts:
- niche vocab too early
- long story lessons WITHOUT targeted vocabulary practice (Story Mode must include vocab list & drills)

---

## 9) Standard Output Requirements (Default Template)
Unless a different Lesson Contract is provided, lessons should follow:

Default template:
- Level: A1
- New vocab: 15-20 total (split across modules)
- Grammar: one point only
- Sentence length: max 7 words

Output must include:
1) Vocab list: ru, stress_cyrillic, en, pronunciation cue
2) 6 example sentences (allowed vocab only)
3) 10 exercises (4 MCQ, 3 fill, 3 translation) MINIMUM
4) Answer key + 1-line explanations
5) Validation results + SRS tags
6) Voice narration metadata (Section 11)

---

## 10) Flashcard-Specific Rules (Quick Reference)
- One card = one objective.
- Front/back must align.
- If English word is ambiguous, label the sense:
  - table (furniture) vs table (data)
- Examples should be minimal and demonstrative.
- If example uses an inflected form, include it as a note/field.

---

## 11) Teacher Voice and Pronunciation Audio (Mandatory Support)

### 11.1 Audio Goals
The app must support:
- Accurate native-like pronunciation for words and sentences.
- Optional teacher voice narration to guide the lesson.
- A user setting to disable narration while still allowing click-to-hear audio.

### 11.2 Audio Modes (User Settings)
The app must expose:
- Narration: ON
  - Teacher voice narrates lesson steps (Teach/Use instructions, brief explanations).
  - Words and sentences are clickable for playback.
- Narration: OFF (Default Recommended)
  - No automatic lesson narration.
  - User can click/tap any word or sentence to hear it.
  - Exercises can optionally provide a “Play audio” button per prompt.
- Pronunciation Only
  - Only target vocab and example sentences have audio.
  - No spoken explanations or instructions.

The AI must generate content compatible with all modes.

### 11.3 Click-to-Hear Requirement (Mandatory)
Every lesson must provide audio hooks for:
- Each target vocab item (base form and stressed form)
- Each example sentence
- Any minimal pair sentences
- Optional: exercise prompts (especially dictation)

Even when narration is OFF, these items must remain playable.

### 11.4 Audio Metadata Fields (Required)
For every item that can be played, output:
- audio_text_ru: exact Cyrillic text to be spoken
- audio_type: word | sentence | dialogue_line | instruction
- audio_scope: click_only | auto_narrate_optional
- audio_note: brief pronunciation note if needed (e.g., “stress on YA”)

Rules:
- audio_text_ru must be Cyrillic-only.
- No transliteration is ever used for TTS input.

### 11.5 Pronunciation Display Rules
Alongside audio, display:
- stress_cyrillic for new words
- optionally IPA (if supported)
- a learner-friendly cue (e.g., syem-YA)
But NEVER use these for audio synthesis.

### 11.6 Narration Script Rules (If Generated)
If narration is ON, narration must be:
- Short and structured (no long monologues)
- Level-appropriate language
- Focused on 1 key idea at a time
- Free of slang and unnecessary filler
Narration must never introduce new vocabulary not taught in the lesson.

### 11.7 Dictation and Listening Exercises
When generating dictation tasks:
- Provide an audio item for the prompt sentence
- Provide a slower playback option if available (metadata flag)
- Provide the correct answer hidden until revealed

### 11.8 Safety + Quality Checks for Audio
Validation must ensure:
- No mixed scripts in audio_text_ru
- No abbreviations that TTS will misread without expansion
- Numbers should be written as words at beginner level (e.g., “два” not “2”) unless the lesson is about numbers

## 12) Transliteration vs Pronunciation (NO HYBRIDS)

### 12.1 Two Separate Fields Only (Mandatory)
The AI must NEVER mix spelling transliteration with pronunciation reduction in the same string.

Always output BOTH fields separately:
- translit_spelling = transliteration matching written Cyrillic letters
- pronunciation_hint = learner-friendly cue approximating actual spoken sound (stress + reduction)

Do not invent hybrid forms like:
zaovut, cmole, semy'a, or anything combining spelling + phonetics.

### 12.2 Transliteration Standard (Spelling-Based)
translit_spelling must map letters consistently (pick one scheme and stick to it):
- Cyrillic-only input → Latin-only output
- No apostrophes for soft sign (ь) in learner mode
- No mixed scripts (no Cyrillic chars inside translit)

Examples:
- зовут → zovut
- столе → stole
- семья → semya

### 12.3 Pronunciation Hint Rules (Sound-Based)
pronunciation_hint is NOT a transliteration scheme. It is a reading cue:
- Must include stress marking via ONE method:
  - caps method: za-VOOT, syem-YA
  - OR stress mark method: zavÚt (only if UI supports it cleanly)
- May reflect vowel reduction (o→a when unstressed), BUT only here.

Examples:
- зовут → za-VOOT (or zavut)
- семья → syem-YA
- пожалуйста → pa-ZHA-luh-sta

### 12.4 Display Rules
- Default UI should show Cyrillic + audio.
- translit_spelling should be optional and hidden after week 1.
- pronunciation_hint can remain available longer, but shown as a hint, not as “the spelling”.

### 12.5 Validation Gate (Hard Fail)
Before publishing:
- ru_text fields must be Cyrillic-only.
- translit_spelling and pronunciation_hint must be Latin-only (plus hyphens/spaces).
- If translit_spelling contains both 'a' and 'o' where Cyrillic contains only 'o' (e.g., “zaovut” for “зовут”), flag as HYBRID and regenerate.

### 12.6 Audio is the Source of Truth
For pronunciation accuracy, rely on audio playback:
- audio_text_ru must always be the Cyrillic text only.
- Never feed transliteration or pronunciation hints into TTS.

## 13) Teacher Persona & Narration (Mandatory)
- Narration Field: Every module MUST include an instructor_narration field.
- Content: Teacher’s voice guidance, encouragement, or explanation spoken to the student.
- Tone: Supportive, English-speaking expert.
- Usage: Display prominently and auto-play if narration enabled at the start of each module.

---

## 14) Extensive Drills (Volume Requirement)
- Minimum 5–8 questions per Drill Module.
- Full lesson should have 15–20 drill questions total.
- Variety: mix selection, typing, matching.

---

## 15) Cyrillic Typography Constraint (UI + Content HARD RULE)
Cyrillic must always render in upright/roman (font-style: normal).
Cyrillic must never use script/handwritten/cursive fonts OR italics.
Emphasis for Cyrillic must use weight (600/700), color, or underline, not italics.
English (Latin) may use script/cursive/handwritten styling.

### 15.1 Implementation Pattern (CSS Example)
Use this pattern to prevent accidental italic/script styling on Cyrillic while still allowing cursive for English:

/* Default UI font */
body { font-family: Inter, system-ui, -apple-system, "Segoe UI", Arial, sans-serif; }

/* Force Cyrillic to stay upright and in a Cyrillic-safe font stack */
:lang(ru), :lang(uk), :lang(bg), :lang(sr), :lang(be) {
  font-style: normal !important;
  font-family: Inter, "Noto Sans", "Roboto", "Segoe UI", Arial, sans-serif;
}

/* Allow cursive only for English */
:lang(en).cursive, .cursive:lang(en) {
  font-family: "Pacifico", "Dancing Script", cursive;
  font-style: normal;
}

### 15.2 Product-side Wording (to avoid “wrong fixes”)
Include these phrases explicitly:
- “No italics for Cyrillic”
- “Cyrillic must use upright roman forms”
- “Use weight/color for emphasis”
